approval — ステップの間で人を待つexample/approval/

ステップの間で signal を待ちます。saga の外側の話なので、ライブラリは関与しません。

forward 補償 子ワークフロー 待ち 実行されない

3つの結末

予約を取ってから承認を待ち、通れば課金します。承認されなかった3通りは、どれも 同じ巻き戻しに合流します。ワークフロー本体はエラーを返すだけです。

▼ 右の3つは同じ
reserve:undo予約を解放する

本体はステップの列のまま。待つ処理も1行です。

res, _ := saga.Step(ctx, s, "reserve", a.Reserve, a.Unreserve, order.ReserveReq{Order: in.Order})
saga.InlineStep(ctx, s, "approval", awaitApproval, nil, ApprovalReq{Wait: wait})
chg, _ := saga.Step(ctx, s, "charge", a.Charge, a.Refund, order.ChargeReq{Order: in.Order})

判断は利用者が書いた関数の中で完結します。アクティビティが「自分の失敗が何を意味するか」を 関数の中に閉じ込めるのと、同じ立ち位置です。

func awaitApproval(ctx workflow.Context, req ApprovalReq) (Decision, error) {
    decision, ok := saga.AwaitSignal[Decision](ctx, ApprovalSignal, req.Wait)
    if !ok {
        return Decision{}, temporal.NewApplicationError("nobody reviewed it", DeniedType, nil)
    }
    if !decision.Approved {
        return Decision{}, temporal.NewApplicationError("rejected by "+decision.By, DeniedType, nil)
    }
    return decision, nil
}
待っている間にキャンセルされても補償は走ります。 切り離した context で 実行されるからで、ワークフロー側は何も書きません。
ステップなので、先が失敗していれば飛ばされます。 ロールバックに 向かっている saga が、人の承認を1時間待って止まることはありません。報告されるのも 最初の失敗で、この待ちが出す「誰も承認しなかった」ではありません。
## 却下されれば予約は取り消される * 承認待ちの注文 "denied" * 却下を送る * saga は "ApprovalDenied" で失敗する * ステップ "reserve, reserve:undo" が実行された * 注文は "reserve" を保持していない
