order — 基本形example/order/

在庫を押さえ、課金し、配送を手配する。どれかが失敗したら、そこまでに起きたことを逆順で取り消す。他の4つはこの形からの派生です。

forward 補償 子ワークフロー 待ち 実行されない

正常系

forward
reserveReserve
→
chargeCharge
→
shipShip
→
Receipt

ship で失敗したとき

forward
reserve
→
charge
→
ship ✕no carrier
▼ 逆順で巻き戻す
補償失敗したステップ自身も取り消す
reserve:undoUnreserve
←
charge:undoRefund
←
ship:undoCancelShipment
失敗した ship も補償されます。 補償はステップを実行する前に 登録されるからです。タイムアウトで失敗したアクティビティは、結果を返せなかっただけで ワーカー上では完走しているかもしれません。ship:undo は「何も予約されて いない」と分かれば no-op で成功します。
## 失敗すると、失敗したステップを含めて逆順に取り消される * "ship" で失敗する注文 "rollback" * saga は "no carrier available" で失敗する * ステップ "reserve, charge, ship, ship:undo, charge:undo, reserve:undo" が実行された * 注文は "reserve, charge, ship" を保持していない

キャンセルされたとき

このライブラリの存在理由にあたる経路。キャンセル済みの context は以降のアクティビティを 即座に失敗させるので、補償は切り離した context で実行します。

reserve
→
charge
→
待機中workflow.Sleep
→
✕ Cancel
▼ NewDisconnectedContext で実行
reserve:undo
←
charge:undo
←
ship:undo未登録（ship は始まっていない）
## キャンセルされた saga もロールバックされる * 課金の後で待機する注文 "cancelme" * "charge" が実行されたら saga をキャンセルする * ステップ "reserve, charge, charge:undo, reserve:undo" が実行された * 注文は "reserve, charge" を保持していない
