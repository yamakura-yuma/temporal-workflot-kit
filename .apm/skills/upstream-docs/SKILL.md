# 上流のドキュメントの引き方

## 既定は指す。写さない

上流が唯一の真実の場所で、`docs/` への複製はキャッシュ。引くのが高くつくときだけ
元が取れる。上流に書いてあることを言い換えただけの段落は、書いた時点から腐り始めるし、
腐っても自分では直せない。

## 写してよいのは2種類だけ

- **上流が黙っている落とし穴** — 使えば必ず踏むのに、公式のどこにも書かれていない挙動。
- **上流のソースを読んで初めて分かったこと** — godoc の一行では読み取れず、実装を
  追って確かめた帰結。

この2つ以外は、書かずにリンクする。

## リンクはバージョンで固定された不変のものにする

散文のドキュメントサイトは再編でパスが消える。代わりに版で固定された URL を使う。

```
https://pkg.go.dev/<module>@<version>/<pkg>#<Symbol>
https://github.com/<org>/<repo>/blob/<tag>/<path>#L<n>
```

版が URL に入っていれば、リンク先は永久に今読んだ内容のまま。散文ページ
（`docs.<product>.io/...` のような、版を持たない URL）を単独の根拠にしない。
併記するのは構わない。

## 写したら出自の行を足す

`docs/sdk-notes.md` に1行足す。モジュール、バージョン、固定 URL、そのリポジトリ内で
その事実が使われている場所。ファイルの先頭には版のスタンプを置く。

```markdown
<!-- upstream: <module> <version> -->
```

**説明そのものはコピーしない。** 出自表は出典だけを持ち、説明は既に書いてある場所に
残す。表が散文の複製になると、腐る面が1つ増えるだけになる。

## 古くなったことは機械で検出する

「定期的に確認する」は守られない。腐る原因は依存のバージョンが上がることなので、
そこに紐付ける。`just docs-check` が出自表のスタンプと依存の実際の版を突き合わせ、
ずれていれば落ちる。

落ちたら表の各行について、上流を開いて次のどれかをする。

1. まだ正しい → スタンプの版だけ上げる
2. 変わった → 説明が書いてある場所を直してから版を上げる
3. 上流が言うようになった / 前提が消えた → 行ごと消し、リンクに置き換える
